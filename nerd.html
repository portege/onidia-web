Written, designed and tested on a Pi 5

Sixty-four bits, end to end.

Onidia and onidia-chat are pure Go, so a build is a single static arm64 binary — nothing to cross-compile on the Pi, nothing to install beside it. The release artifact is exactly that: one arm64 .deb that carries both halves. A Raspberry Pi 5 is what they were written against, designed around and tested on.

The more interesting half is what that Pi can be as the machine. On a AI HAT+ 2 — the Hailo-10H board, 40 TOPS of INT4 inference and 8 GB of RAM living on the card itself — Hailo's hailo-ollama speaks the very same ollama /api/chat dialect onidia-chat already speaks to the network. Point the provider at localhost and the model stops being someone else's computer.

Nothing leaves the Pi. No key, no account, no request to a vendor you cannot audit — pull the network cable and it behaves identically. One honest footnote: hailo-ollama rejects the tools field, so onidia-chat retires tool calling after the first reply and carries on in plain text.

How a frame is made

A tiny state machine — idle, walk, hop, drag, throw — runs a few physics steps a frame and produces a pose: bob, leg swing, foot lift, blink, arm flags, expression. The pose is rendered procedurally onto a supersampled canvas and downsampled for smooth edges, the speech bubble is composed above it, and the whole image is uploaded with a single PutImage. The window itself just moves to follow her.

Because the character is code and not a sprite sheet, adding a personality means writing a Go package: its own palette, drawing functions and phrase list, registered at startup and picked with -character. Two characters can never collide, because they share nothing but the pose contract.

XShape is deliberately not used: under XWayland, shrinking a shaped window's region can stop updates from being presented, so the plain transparent window composites correctly everywhere instead.
